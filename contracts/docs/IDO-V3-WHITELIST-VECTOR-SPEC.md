# IDO V3 whitelist v1 — cross-language vector specification

Status: local development contract, **not production governance approval**. Canonical cases: `test/fixtures/ido-v3-whitelist-v1.json`; executable generator and tests: `scripts/lib/idoV3Whitelist.js`, `test/IDOv3WhitelistVectors.test.js`, `test/JoinCareIDOv3Whitelist.test.js`.

1. Project scope is the exact positive uint256 `chainId` and `projectId`, plus the new V3 **proxy** address. Never use the V2 proxy, implementation address, latest global contract setting, or an imprecise JavaScript Number for a Sonyflake project ID.
2. Interpret every buyer as a valid, nonzero 20-byte EVM address. Compare addresses case-insensitively for duplicate detection. A disabled policy has `root=0x00...00`; an enabled policy has at least one member and a nonzero root. Empty, duplicate and ambiguous wallet input fail closed.
3. `schema = keccak256(UTF8("JOINCARE_IDO_V3_WHITELIST_LEAF_V1"))`. Each leaf is `keccak256(abi.encode(schema, chainId, proxyAddress, projectId, buyerAddress))`; **not** `abi.encodePacked` and not a raw address hash. Go and browser implementations must match every committed vector's leaf bytes exactly.
4. Sort leaves in ascending 32-byte numerical order (equivalently lexicographic order of lowercase fixed-length 0x-prefixed hex). Pair adjacent nodes and hash as `keccak256(concat(min(nodeA,nodeB), max(nodeA,nodeB)))`, compatible with OpenZeppelin `MerkleProof.verifyCalldata`. Promote an unpaired odd node **unchanged** to the next level; never duplicate it. Repeat until one root remains. A one-wallet root equals its leaf and its proof is empty.
5. A proof lists siblings bottom-up; at each level add the adjacent node if present, then advance to `floor(index / 2)`. Missing sibling on an odd level contributes no proof item. `purchaseWithProof(projectId, amount, expectedVersion, proof)` verifies the currently stored root and version against `msg.sender` when the transaction executes; a changed version makes a cached proof stale even if membership happens to remain unchanged.
6. Root alone cannot prove how many wallets are included or who they are. Approval must bind an immutable sorted full-member snapshot/digest to the new root, expected old version, project identity, approvers and chain execution evidence. The contract verifies proof membership, not the correctness of off-chain admin approval or snapshot retention.

The test mock `IDOv3TwoOfThreeGovernorMock.sol` proves only that contract-call authority can be separated from the single operator in a local Hardhat run. It is **not** a production Safe or an authorization/nonce/reorg system. The real governance threshold, signer custody, upgrade authority and Admin-to-chain evidence are release blockers. Do not deploy this mock to production.

## Offline complete-member snapshot commitment v1

Canonical fixture: `test/fixtures/ido-v3-snapshot-v1.json`, built from the same 1/2/3/5 member scopes above. `snapshotSchema = keccak256(UTF8("JOINCARE_IDO_V3_WHITELIST_SNAPSHOT_V1"))`. Concatenate every 32-byte **sorted leaf**, then `membersDigest = keccak256(concat(sortedLeaves))`. `digest = keccak256(abi.encode(snapshotSchema, chainId, proxyAddress, projectId, targetVersion, root, membersDigest, memberCount))`, with uint256 slots for chainId, projectId, targetVersion and memberCount. `targetVersion` is a nonzero uint64. Preserve the full ordered member set, not merely root/count/digest. Go/JS tests independently recompute this digest from the fixture; input order cannot change it. The snapshot digest is only an offline **candidate** for immutable four-eye approval; it neither binds signers nor establishes on-chain execution, finality or the authenticity of a provided full snapshot. Production approval must also bind expected old version, action, approvers and execution evidence, then compare an independently finalized policy read to the approved candidate.
