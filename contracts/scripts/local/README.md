# Fair Launch strictly LOCAL-ONLY persistent Contract fixture

Production/default deployment, migration, Backend materialization, online release and public networks remain **NO-GO**. This Contract fixture is an additive browser-test lane only. It accepts one explicit run ID and one exact `http://127.0.0.1:<port>` endpoint, requires chain ID 31337, rejects production/private-key/mnemonic environment variables, and never reads Deploy/Backend state.

## Persistent commands

Compile once with the same exact local RPC identity:

```bash
JC_FAIR_LAUNCH_LOCAL_E2E_RPC_URL=http://127.0.0.1:19141 \
  npm run compile:fair-launch:local-e2e
```

Start, deploy, inspect and stop:

```bash
npm run fair-launch:local-e2e:start -- \
  --run-id 07d34b77-932b-446f-83a0-a93b27585f25 \
  --rpc-url http://127.0.0.1:19141

npm run fair-launch:local-e2e:deploy -- \
  --run-id 07d34b77-932b-446f-83a0-a93b27585f25 \
  --rpc-url http://127.0.0.1:19141 \
  --trust-pin /orchestrator/authority/fair-launch-contract-pin.json

npm run fair-launch:local-e2e:status -- \
  --run-id 07d34b77-932b-446f-83a0-a93b27585f25 \
  --rpc-url http://127.0.0.1:19141 \
  --trust-pin /orchestrator/authority/fair-launch-contract-pin.json \
  --trust-pin-sha256 <pin-digest-returned-by-deploy> \
  --manifest-sha256 <manifest-digest-returned-by-deploy>

npm run fair-launch:local-e2e:frontend-admission -- \
  --run-id 07d34b77-932b-446f-83a0-a93b27585f25 \
  --rpc-url http://127.0.0.1:19141 \
  --trust-pin /orchestrator/authority/fair-launch-contract-pin.json \
  --trust-pin-sha256 <pin-digest-returned-by-deploy> \
  --manifest-sha256 <manifest-digest-returned-by-deploy>

npm run fair-launch:local-e2e:stop -- \
  --run-id 07d34b77-932b-446f-83a0-a93b27585f25 \
  --rpc-url http://127.0.0.1:19141
```

The default state root is outside the repository at `<OS temp>/joincare-fair-launch-contract-e2e/<run-id>`. On Linux/WSL it is `/tmp/joincare-fair-launch-contract-e2e/<run-id>`. Directories are owner-only and authority/evidence files are create-once mode 0600 where supported. `start` returns only after exact RPC/chain/genesis readiness. `status` and `stop` revalidate the recorded supervisor and Hardhat child by exact PID, process start identity, executable and command line. They never kill by name or port. Evidence remains after stop.

Hardhat stdout/stderr are intentionally discarded so its deterministic test-account banner is never retained. Deploy publishes a separate create-once public trust authority bound to the root/process authorities, run, RPC and current genesis, and requires an explicit external `--trust-pin` path outside the Contract run directory. Deploy creates that pin once and returns `trustPinSha256`, the SHA-256 of the exact canonical pin bytes. The orchestrator must retain that digest plus deploy's returned `manifestSha256` outside all Contract run/trust/manifest authority and supply both explicitly as `--trust-pin-sha256` and `--manifest-sha256` to status, frontend admission, and future consumers. Manifest publication and consumption use exact canonical bytes plus stable file identity checks; a path alone is never authority. Deploy retries and consumers fail if the explicit lowercase digest is absent or differs, even if the pin, trust record, and manifest are all coherently replaced. The signed deployment envelope is admitted only against that external key and current live code identities. It contains only public addresses/code hashes and an Ed25519 public JWK/signature. The private signing key is generated by the deploy parent, passed to the worker over inherited stdin only, and never written, logged, exported through environment/cmdline, or returned. The envelope is compatible with the Frontend `fair-launch-local-e2e-env.js` generator and contains active successful project `102`, an active high-soft-cap project `101` for the later failed branch, and already-cancelled project `103`.

Browser faucet policy is manifest-declared and test-only: `FairLaunchTokenMock.mint(address,uint256)` may mint payment tokens to the connected wallet. A future Frontend helper may provision native gas only by the exact admitted loopback Hardhat RPC method `hardhat_setBalance`; there is no private-key API.
