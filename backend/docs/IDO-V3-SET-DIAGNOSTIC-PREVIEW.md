# V3 Set diagnostic preview (not Set admission)

For an unassigned, unlocked `Setup / capped_presale` project without a V3 binding, the Admin `onchain-params/preview` endpoint can now validate V3 terms without an offline Set signature or an `ido_v3_runtime` enrollment. This is a **read-only diagnostic**, not an approval, Set, project binding, create transaction or wallet eligibility.

The preview requires the pinned BSC 56 V3 Proxy and Implementation bytecode and slot, Owner Safe, Policy Safe address and deployed code, operator address, a valid live fee receiver and bounded live fee rate, USDT and the selected project's distinct token address/decimals/`allowed` configuration, and a stable 15-confirmation block. The selected project token is not inferred from TESTCAT; it must already be admitted by the actual Owner Safe. It uses only the separately approved V3 token-admission commercial RPC and never falls back to V2 identity. Payment/token terms are converted with their respective V3 decimals. The separately signed scanner and wallet gates remain unchanged. This read-only check is not independent two-provider corroboration.

**V3 write remains separately gated**: Admin can submit a V3 Set for approval only after the existing signed Set continuity and unverified runtime have independently passed admission; approval application rechecks it. The diagnostic preview alone is insufficient. Disabling only these checks at Set while leaving Create/scanner tied to the signed manifest would strand a project as `Set` with no viable create path. An unsigned Set flow, if desired, must be designed and reviewed across the persisted commitment, create and scanner continuity before any production write is enabled. No database migration or runtime toggle is part of this preview change.

Do not treat a successful preview or a locally built package as an online feature. It requires a separately authorized Backend/Admin deployment and a production read-only acceptance check.

The address-based project-token admission page is a separate Safe-governed step for future project tokens. It does not enroll a project runtime, supply a Set signature, create a project, enable scanner/proofs, or support arbitrary payment currencies: this V3 path still uses the pinned BSC USDT payment token. No part of this change grants general "all projects can open IDO" authority.
