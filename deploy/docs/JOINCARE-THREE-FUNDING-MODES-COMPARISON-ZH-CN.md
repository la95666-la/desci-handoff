# JoinCare 三种融资模式对比表

> 本表与《JoinCare 三种融资模式简介》配套。Standard TGE 超额认购仅为拟新增方案，**尚未实现或开放**。现有合约/系统路径也不等于生产融资运行权限已启用。

## 一、融资规则对比

| 对比项 | 固定价软/硬顶预售（现有 IDO V2） | Fair Launch（现有 V1） | Standard TGE 超额认购（拟新增） |
|---|---|---|---|
| 定价 | 募资前固定 | 募资结束后由最终募集额 / 固定销售 Token 量确定 | 募资前固定 |
| 销售 Token | 按固定价格及已存储备销售 | 销售总量预先固定，激活前精确存入 | 销售总量预先固定，需预存足额 Token |
| 成功门槛 | Soft Cap | Soft Cap | 可设置，具体规则待定 |
| 募集目标 / 上限 | 有 Hard Cap | 无独立 Hard Cap 字段；**当前合约 `maxContribution` 同时限制项目总募集接纳额** | 固定**目标成交额**；允许认购总额超过目标 |
| 超过目标的认购 | 超出 Hard Cap 的交易直接失败 | 超出当前 `maxContribution` 实际总额限制的交易直接失败 | 先记录有效认购，期末按比例成交并退回未成交款 |
| 达到门槛/上限后 | 达到 Soft Cap 不必结束；恰好满 Hard Cap 可提前结算 | 达 Soft Cap 不提前结算；达当前总接纳上限则拒绝新贡献，等待 `endTime` | 超额报名仍可持续至截止时间；期末统一结算 |
| 用户最终 Token 数量 | 认购时按固定价格确定 | 期末按贡献额 / 最终募集额分配 | 期末按成交比例及固定价格确定 |
| 用户实际付款 | 成功时保留全部已接受认购额 | 成功时保留全部已接受贡献额 | 成功时只保留实际成交额 |
| 成功项目是否退未成交款 | 不涉及；没有超募部分成交 | 不退 Soft Cap 以上的贡献款 | **退回超募未成交部分** |
| 失败/取消退款 | 已认购金额按链上规则退回 | 已贡献金额按链上权威状态退回 | 拟全额退款，机制尚待设计 |
| 支付资产 | 准入 ERC-20 支付 Token | 准入稳定币；不直接接受原生 BNB | 稳定币优先；若支持原生 BNB 须另建收付及计价机制 |
| Alpha Points 准入 | 当前合约不原生支持 | 当前合约不原生支持 | 可设计为链上可验证门槛/额度，尚未实现 |
| 成功资金归属 | 按实际认购额计算项目收益与平台费 | 按最终已接受贡献总额计算收益与平台费 | **仅按实际成交额**计算收益与平台费，超募退款须独立留存 |
| Vesting | 支持分期 Claim | 支持分期 Claim | 可设计支持，尚未实现 |
| 产品/开发状态 | 已有合约与系统路径，不等于当前生产已开放 | 已有合约与系统路径，金融运行权限仍需独立启用 | **仅方案，需独立开发、审计、迁移、E2E 与授权** |

## 二、一句话区分


- **固定价软/硬顶预售：**价格、Hard Cap 固定；先到先得，满额即止，超额交易失败。
- **Fair Launch：**销售 Token 量固定、最终价格浮动；成功时保留全部有效贡献，但当前合约有 `maxContribution` 总接纳上限。
- **Standard TGE 超额认购：**价格和目标成交额固定；允许超募，期末按比例成交，成功项目退还未成交款；**当前尚未实现**。

---

### 依据与边界

- 现有预售：`JoinCareIDOv2.sol` 的 `createProject`、`purchase`、`endProject`、`refund` 和 `claim`。
- 现有 Fair Launch：`JoinCareFairLaunchV1CoreFacet.sol`、`JoinCareFairLaunchV1FundsFacet.sol`、`JoinCareFairLaunchV1Shared.sol` 和 `IDO-FAIR-LAUNCH-DEVELOPMENT-DESIGN.md`；特别以当前 `contribute()` 的总额校验为准。
- Standard TGE：仅依本次提出的“固定价、超额认购、按比例成交、未成交资金退款”需求描述，不宣称已有合约、接口或生产能力。
