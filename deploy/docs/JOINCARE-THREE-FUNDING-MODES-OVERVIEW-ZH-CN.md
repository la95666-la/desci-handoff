# JoinCare 三种融资模式简介

> 文档用途：供项目方、运营及产品讨论选择融资模式；不替代链上参数确认、合约审计或法律意见。
> 状态说明：**固定价软/硬顶预售**与 **Fair Launch** 为现有代码定义的模式；**Standard TGE 超额认购**是拟新增方案，**尚未在当前系统实现或开放**。现有代码/链上部署不代表已获生产运行权限。具体上线需以已审批的合约版本、部署与运行门禁为准。

## 一、固定价软/硬顶预售（Capped Presale / IDO V2）

**特点：**项目方预先确定 Token 价格、最低成功融资额（Soft Cap）和募集上限（Hard Cap）。用户认购时即按固定价格计算购买的 Token 数量；认购总额不能超过 Hard Cap。这是“先到先得的限额预售”，**不是**允许超额认购后再按比例分配的模式。当前 V2 使用平台准入的 ERC-20 支付 Token，不把原生 BNB 视为默认支付资产。

**融资流程：**

1. 项目方和平台确认价格、Soft Cap、Hard Cap、每钱包上限、时间窗及 Vesting，创建链上项目。
2. 项目方存入所需销售 Token；满足激活所需储备后，项目进入 Active。
3. 用户在募资期按固定价格认购。超过个人上限、Hard Cap 或可销售 Token 储备的交易直接失败，不先收款再部分成交。
4. **募集额恰好达到 Hard Cap 时可提前结算**；否则在结束时间后结算。达到 Soft Cap 的项目成功，项目方和平台按合约规则提取款项，用户按 Vesting 领取 Token。
5. 未达到 Soft Cap 或项目取消时，用户按已认购金额退款；项目方依规则取回未售 Token。

**适合：**项目方希望提前锁定销售价格及融资总额，并接受先到先得、满额即停止的发行方式。

## 二、Fair Launch（固定销售量、结束后统一浮动定价）

**特点：**项目方固定本轮销售 Token 总量并设置 Soft Cap，**不预设最终 Token 单价**。成功项目在募资结束后，按最终募集额统一确定价格，用户依贡献占比分配 Token。成功项目的已接受贡献**不因“超出 Soft Cap”而退还差额**；未达 Soft Cap 或取消才按相应链上状态退款。当前 V1 使用平台准入的稳定币支付，流动性由项目方自行安排（Manual），不自动建池或锁 LP。

**融资流程：**

1. 确认销售 Token 总量、Soft Cap、支付币、贡献限制、时间窗和 Vesting；项目方在激活前向合约**精确存入全部销售 Token**。
2. 在 Active 募资期，用户贡献稳定币。页面展示的价格和预计 Token 份额会随总募集额变化；达到 Soft Cap **不会提前结算**。
3. 到结束时间后执行链上结算：低于 Soft Cap 则 Failed、用户全额退款；满足成功条件则先进入 `SuccessfulPendingRelease`，冻结最终总额和价格。
4. 成功项目通过确认数、运行身份核验、对账及 Release Gate 后才成为链上 `Successful`。之后用户按 Vesting Claim；项目收益 Safe 提取扣除平台成功费后的募集款。

**当前合约特别提示：**实际 V1 `contribute()` 同时以 `maxContribution` 限制**单钱包累计贡献**和**项目累计募集额**。在 BSC 主网，该参数必须非零；项目总额触及它时，超额交易直接失败，但项目仍等待结束时间才结算。这相当于一个**实际总接纳上限**，与早期仅称其为“单钱包上限、没有总额上限”的设计描述不一致。对外介绍、项目参数和前端展示应以实际部署版本复核，不得宣传为“无限接受超额贡献”。

**适合：**项目方接受最终价格随有效募集额浮动、按贡献占比瓜分固定 Token 池，且能够充分披露当前合约总接纳上限的项目。

## 三、Standard TGE（固定价格、超额认购后按比例成交；拟新增）

> **仅为产品方案，不是当前 JoinCare 已上线或可调用的融资模式。**它与上述两种模式均不同：需独立设计合约、账本、成功退款和准入机制。

**特点：**事先确定销售 Token 数量、固定价格和目标成交额。认购期允许总认购额超过目标；结算时，按认购比例确定每个用户实际成交额和 Token，**成功项目仍需退还每人未成交的款项**。Alpha Points 门槛/额度是可选的拟议准入规则，不是当前两种模式的链上原生能力。

**融资流程（拟议）：**

1. 确定 Token 销售量、固定价格、目标成交额、认购时段、个人额度及适用的资格规则；项目方事先存入足额销售 Token。
2. 用户通过链上可验证的资格/额度检查后认购。合约记录个人认购额和总认购额，**允许总额超过目标成交额**；募资期显示的成交比例、可获 Token 和退款额只是预估。
3. 募资结束后，链上冻结总认购额。若未超募，符合成功条件的认购按固定价格成交；若超募，按个人认购额占总认购额的比例分配目标成交额和 Token。
4. 用户分别领取成交 Token（可按 Vesting）及**未成交资金退款**；项目方只能提取实际成交额扣除平台费的净额。若未达到约定最低成功门槛或项目取消，则按另行冻结的规则全额退款。

**100 倍超募示意（忽略链上精度与舍入）：**目标成交 `1,000 BNB`，总认购 `100,000 BNB`，某用户认购 `3 BNB`。该用户实际成交约 `0.03 BNB`，约 `2.97 BNB` 退回。其 Token 按**实际成交金额与固定价格**计算；项目方实际成交总额约为 `1,000 BNB`，不是 `100,000 BNB`。

**需要先明确的规则：**如果“Token 价格为 `$0.05`”而用户以 **BNB** 认购，BNB/USD 汇率会波动，必须先选定固定的 BNB/Token 计价，或设计明确的美元报价预言机、取价时点及失败处理；不能直接用美元固定价和 BNB 募资额混算。用户资格、退款期限、舍入尾差、未售 Token 和失败门槛也须另行确定。

**适合：**项目方要锁定销售价格及最终成交规模，希望开放超额报名，并让所有合格认购者按比例获得成交份额。

## 四、选择建议

- **固定价软/硬顶预售：**价格、Hard Cap 固定；先到先得，满额即止，超额交易失败。
- **Fair Launch：**销售 Token 量固定、最终价格浮动；成功时保留全部有效贡献，但当前合约有 `maxContribution` 总接纳上限。
- **Standard TGE 超额认购：**价格和目标成交额固定；允许超募，期末按比例成交，成功项目退还未成交款；**当前尚未实现**。

- 现有预售：`JoinCareIDOv2.sol` 的 `createProject`、`purchase`、`endProject`、`refund` 和 `claim`。
- 现有 Fair Launch：`JoinCareFairLaunchV1CoreFacet.sol`、`JoinCareFairLaunchV1FundsFacet.sol`、`JoinCareFairLaunchV1Shared.sol` 和 `IDO-FAIR-LAUNCH-DEVELOPMENT-DESIGN.md`；特别以当前 `contribute()` 的总额校验为准。
- Standard TGE：仅依本次提出的“固定价、超额认购、按比例成交、未成交资金退款”需求描述，不宣称已有合约、接口或生产能力。
